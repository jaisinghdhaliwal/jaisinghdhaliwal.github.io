Design/Start here/Accessibility

Accessible by default

The portfolio should communicate Jai’s attention to detail to as many people as possible. Accessibility is a quality standard applied throughout colour, typography, motion, media and code.

On this page Baseline Colour & type Keyboard & touch Motion Media Release checklist

01 / Baseline

Design for different ways of seeing and moving.

Every page must remain understandable with zoom, keyboard navigation, reduced motion, high-contrast preferences and media that has not loaded. Progressive enhancement should add polish rather than unlock the basic experience.

01

Use meaningful structure

Follow one logical heading order, use landmarks, label navigation regions and use buttons and links according to their real behaviour.

02

Keep content available

Project names, country choices and core contact information remain visible without hovering, autoplay or JavaScript.

03

Test the real pages

Automated checks are a starting point. Test keyboard use, screen-reader announcements, mobile zoom, slow media and reduced-motion behaviour manually.

02 / Colour & typography

Brand colour never overrides legibility.

The primary dark is the default text colour on paper and white. Coral is primarily a signal for selection, emphasis and large display moments—not a replacement for readable body text.

Do

Keep body copy at the shared Poppins size and allow text to reflow at 200% zoom without clipping or horizontal page scrolling.

Avoid

Do not use opacity alone to create secondary text, place fine coral text over photography or communicate selection through coral alone.

03 / Keyboard, pointer & touch

The same destination, however it is reached.

Hover is an enhancement. Every hover interaction requires an equivalent focus and tap experience, and the order of controls must follow the visual reading order.

Keyboard

  • Show a visible focus indicator.
  • Keep focus out of closed menus.
  • Return focus when overlays close.
  • Support Escape for modal navigation.

Touch

  • Provide comfortable, separated targets.
  • Keep the full three-item navigation visible.
  • Do not enlarge the navigation on touch hover.
  • Never require precise dragging to view content.

04 / Motion

Movement should orient, not interrupt.

Page transitions, viewport reveals, the moving navigation pill and carousel motion all need a reduced-motion alternative.

01

Respect the user preference

When prefers-reduced-motion is enabled, remove travel, parallax and autoplay. Content appears immediately without losing information.

02

Pause continuing motion

Photography carousels and showreels need a clear pause control whenever movement continues beyond a short transition.

03

Do not flash

Avoid rapid brightness changes, especially when combining HDR project media, white pages and dark video frames.

05 / Images, video & 3D

Describe the work without duplicating it.

Alternative text should communicate why an image matters in context. Decorative lighting textures and repeated logo marks can use empty alternative text.

06 / Release checklist

Check before publishing.

  1. Navigate every interactive element using only the keyboard.
  2. Confirm headings and landmarks describe the page structure.
  3. Test at 200% browser zoom and at a narrow mobile viewport.
  4. Verify text/background contrast at the actual rendered size.
  5. Enable reduced motion and confirm all content remains available.
  6. Pause autoplay media and confirm the control is labelled.
  7. Disable images and check that alternative text remains useful.
  8. Test project cards and navigation with touch as well as hover.
  9. Check that focus is not hidden beneath fixed navigation.
  10. Run automated checks, then complete a manual pass.
