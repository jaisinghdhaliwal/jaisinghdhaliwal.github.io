Design/System/Components

Interface components

A small, repeatable set of controls and content patterns for Jai’s portfolio, Create archive and web CV. Components should feel tactile without competing with the work they contain.

On this page Principles Navigation Actions Project cards Selectors Interaction states

01 / Component logic

Familiar first. Distinctive second.

The system’s personality comes from careful spacing, restrained depth, coral signals and smooth motion. The underlying interaction should remain immediately understandable.

01

One component, one job

A button performs an action, a link changes location and a selector changes the visible set. Do not make visually identical controls behave differently.

02

Coral indicates intent

Use coral for the current page, the selected option and the primary action. It should not become a general-purpose background colour.

03

Depth responds to interaction

Shadows and small changes in elevation may reinforce hover or focus. Keep the content stable and never make touch users depend on a hover-only reveal.

02 / Navigation

Persistent, compact and recognisable.

The portfolio navigation keeps all three destinations visible. A coral pill marks the current page; a white pill may preview another destination on hover or focus.

03 / Actions

Give every page one clear next step.

Primary buttons are reserved for the action Jai most wants the visitor to take. Secondary buttons remain outlined or neutral so the hierarchy is obvious.

Primary action

Download CV

Use once within a decision area. Labels begin with a direct verb.

Secondary action

View portfolio

Use for a useful alternative that should not compete with the primary action.

Do

Use concise labels such as “Download CV”, “View project” or “Open in AR” when that action is genuinely available.

Avoid

Do not use vague labels such as “Click here”, stack several coral buttons together or add icons that repeat the words.

04 / Project cards

Artwork gets the space. Metadata stays useful.

Project tiles use a consistent footprint while allowing the artwork itself to vary. The glass caption remains inset from every edge and never covers more of the image than necessary.

05 / Selectors

Selection changes content in place.

Country selectors and documentation tabs use the same selected-state logic, but their layout can adapt to the available width.

Responsive-state guidanceInteractive example

Pointer

Hover can preview interactivity through a white surface, light elevation or stronger shadow. The resting state must still communicate the control’s purpose.

Touch

Do not scale the entire navigation on touch. Keep targets comfortably sized and make the selected state persistent after a tap.

Keyboard

Focus follows the same visual family as hover but includes a visible outline. Tab order must match the reading order.

06 / States

No hidden interaction contracts.

Every interactive component requires a default, hover, focus-visible, active and unavailable state where relevant.
