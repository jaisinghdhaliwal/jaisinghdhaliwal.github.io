02 / Understanding the metrics

Quick to appear. Stable as it loads.

01

First and largest contentful paint

FCP measures when the first text or image appears. LCP measures when the largest visible content element appears. Prioritise the opening image and the resources needed to show it.

02

Blocking time and layout shift

TBT measures blocking time from long main-thread tasks during loading. CLS measures unexpected layout movement and has no time unit. Keep JavaScript light and reserve space for media before it arrives.

03

Speed Index

Speed Index measures how quickly the visible page fills in. Avoid hiding the initial content behind delayed animations, even if the underlying files have already loaded.

These are lab measurements from one saved run, not real-user Core Web Vitals. Mobile and desktop use different test conditions; neither represents every visitor’s connection or device.

03 / Optimisation standards

Keep the visual quality. Reduce the overhead.

01

Load the visible work first

Give the opening image priority. Use appropriately sized thumbnails and defer off-screen galleries, video and 3D assets. Do not preload every project just because it is available.

02

Choose media for its purpose

Use compressed AVIF or WebP images where suitable, SVG for vector artwork and video for longer animation. Compare file size with visual quality and decoding cost. A carousel thumbnail should not download the full-size photograph.

03

Make the first frame stable

Reserve the correct media dimensions. Match video posters to the video’s crop and position, and avoid font changes that move the surrounding content. The page should remain useful before video playback starts.

04

Reuse the system

Use shared typography, components and styles rather than duplicating them. Keep scripts focused on necessary behaviour, avoid repeated layout measurements and delay non-essential carousel activity until the initial content is ready.

05

Account for third-party content

Video embeds and analytics add requests and processing work. Measure their impact when adding or changing them, and keep the core page usable if a visitor blocks them.

04 / Before publishing

Check the experience, not just the number.

  1. Run PageSpeed Insights on mobile and desktop for the homepage and representative Create, CV and project pages.
  2. Repeat tests before attributing a small score change to a code change. Compare individual metrics under equivalent conditions.
  3. Check loading on an actual phone, including a first visit without cached files.
  4. Watch for poster flashes, late font changes, layout movement and controls that do not respond promptly.
  5. Test with reduced motion, keyboard navigation and blocked third-party scripts. Follow the accessibility checklist alongside the automated audits.
  6. Record the tested URL, date and report links when updating this reference. Keep historical results clearly separate from current measurements.
