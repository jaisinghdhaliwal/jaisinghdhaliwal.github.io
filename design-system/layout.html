Design/Foundations/Layout & spacing

Structured space.
Flexible content.

A shared shell, readable measure and fluid spacing keep the identity consistent from a narrow phone to a wide desktop—without maintaining separate designs for every device.

On this page Principles Page shell Grid Spacing Responsive behaviour Composition

01 / Principles

Use constraints to create calm.

The layout system is intentionally small. A consistent outer shell, a maximum reading measure and a limited spacing rhythm do most of the work.

01

Fluid before fixed

Use flexible tracks, percentages, minmax() and clamp() so a component can adapt across the full width range.

02

Break only when structure changes

A breakpoint should alter hierarchy or composition—not compensate for arbitrary fixed widths.

03

Share behaviour across modes

Desktop, tablet and mobile should use the same component rules wherever possible. Media queries refine the layout rather than replace it.

04

Let imagery choose its crop

Keep the intended focal point visible and use intrinsic aspect ratios where the format does not require a standardised tile.

02 / Page shell

One outer edge anchors every page.

The shell centres content and protects it from both narrow viewports and excessively long line lengths. Full-bleed media may leave the shell, but its labels and aligned edges should reconnect to it.

Current shell
Wide min(1320px, 100% - 80px): up to 1320px with 40px side gutters.
Compact Below 1040px: up to 1180px with 24px side gutters.
Small Below 800px: 100% − 32px, giving a 16px gutter on each side.
Reading measure 760px maximum for paragraphs, lists and other continuous copy.
Header height 76px by default; 68px below 800px.

03 / Grid

Use the smallest grid that explains the content.

Columns are a compositional tool, not a requirement. Start with the content relationship and choose the simplest grid that makes it understandable.

Documentation 220px local-navigation rail plus one flexible content column. The gap scales from 52px to 112px.
Portfolio work Three equal project columns on wide desktop, reducing only when a card can no longer preserve its content and target size.
Comparisons Two equal columns for do/avoid guidance, component states and paired applications.
Editorial imagery A twelve-column composition allows mixed image widths while retaining common alignment points.
Reading pages Use one main text column. Do not add columns merely to fill an empty desktop viewport.
Do

Align related edges

Headings, body copy, images and controls should share a small number of strong vertical lines.

Avoid

Forcing every module into twelve columns

The grid should simplify the page. A two-column relationship does not need twelve separate calculations.

04 / Spacing

A limited rhythm creates hierarchy.

The working set below reflects values already present in the interface. Use the nearest shared value before introducing a new one.

8px Tight inline gaps, local navigation items and metadata separation.
12px Label-to-content gaps and compact control spacing.
16px Small-screen gutters, card internals and standard grid gaps.
24px Default card padding and heading-to-copy relationships.
32px Section internals, larger card padding and compact composition gaps.
48px Major group separation and compact page gutters.
64px Mobile section separation and document content entry.
72px Default separation between adjacent documentation sections.
88–120px Large section endings, page padding and major desktop transitions.

05 / Responsive behaviour

Three thresholds, one continuous system.

Breakpoints describe meaningful changes in composition. Values between them remain fluid, so intermediate widths should never feel like an unsupported “middle ground”.

Threshold Purpose Typical change
1040px Compact / tablet Reduce gutters, simplify dense grids and stack wide hero compositions where needed.
800px Small / touch-first Move local navigation into a horizontal sticky rail, stack document columns and reduce header height.
560px Narrow refinement Collapse paired cards and complex grids to one column and simplify secondary branding text.
01

Preserve the reading order

CSS reflow must not create a different logical or keyboard order from the document.

02

Keep touch targets generous

Controls should remain comfortably operable when the visual layout becomes denser. Do not shrink navigation simply to preserve a desktop row.

03

Test intermediate widths

Check the full resize range, especially around long headings, location diagrams, carousels and fixed navigation.

06 / Composition

Whitespace is an active part of the identity.

Do

Keep a strong visual entry point

Each viewport should make the title, current section or primary piece of work immediately understandable.

Avoid

Filling empty areas by default

Open space supports the minimal identity and separates interface chrome from colourful work.

Do

Use overlap with a reason

Glass captions may overlap imagery when they identify it, but the image should retain enough unobstructed space to remain the focus.

Avoid

Absolute positioning core content

Text and controls should participate in normal layout so they reflow reliably and remain accessible.

Do

Let modules share tokens

Project cards, CV panels and documentation examples should use the same radii, shadows and gaps where their hierarchy matches.

Avoid

Duplicating breakpoint rules

If width clamping or a shared grid can solve the behaviour once, do not maintain separate tablet and mobile declarations.
