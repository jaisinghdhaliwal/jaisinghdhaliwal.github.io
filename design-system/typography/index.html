01 / The system

Two families, two distinct jobs.

The system stays recognisable by limiting itself to two local web-font families. Poppins handles all expressive and long-form reading. Fira Code handles compact navigation, labels, metadata and specification content.

Primary family Poppins — regular 400 and bold 700 files are supplied locally.
Technical family Fira Code — local WOFF2 with a working weight range from 300 to 700.
Default body 16px / 1.5, Poppins regular, body ink on light surfaces.
Default label 19px / 1.2, Fira Code bold, uppercase. Compact utility labels may reduce to 13px when space is constrained.

02 / Poppins

The human voice.

Poppins is the main reading and display family. Its geometric construction connects to the logo, while its rounded forms keep the system approachable rather than clinical.

03 / Fira Code

The system voice.

Fira Code adds a measured technical rhythm. It is used where text behaves like navigation, a tag, a timestamp, a specification or a concise instruction—not for paragraphs.

Use for

Short system language

Navigation, section kickers, project metadata, dates, buttons, file information and tokens.

Do not use for

Reading copy

Introductions, project stories, CV descriptions and long instructions should remain in Poppins.

04 / Hierarchy

Scale should clarify, not decorate.

Large Poppins headings establish each page. Bold Poppins subheadings organise the detail, body copy explains and Fira Code provides consistent orientation cues.

01

Page display

Poppins 700, tightly tracked and fluid from 48px to 96px.

02

Section label

Fira Code 700 at 19px with a structural rule. Use concise uppercase language to divide major content groups.

03

Subheading

Poppins 700 at 19px with 1.5 line height. It connects headings to the 16px reading layer without introducing another display scale.

04

Body copy

Poppins 400 at 16px with 1.5 line height and a maximum reading width of 760px.

05

Label and utility

Fira Code 700 at 19px for visible content labels; 13px is reserved for compact controls, breadcrumbs and technical metadata.

06 / Usage

Fewer styles make the hierarchy stronger.

Do

Use sentence case for headings

It feels more direct and readable. Reserve full capitals for short Fira Code labels.

Avoid

Creating page-specific sizes

Documents, project pages and image-led layouts should share the same hierarchy instead of inventing local scales.

Do

Keep paragraphs readable

Limit long copy to approximately 60–75 characters per line and retain generous paragraph spacing.

Avoid

Using Fira Code for personality alone

The monospace family should communicate function. Decorative overuse makes the system feel retro-tech rather than contemporary.

Do

Use only supplied weights

Poppins regular and bold cover the current hierarchy without relying on synthetic browser weights.

Avoid

Compressing line height on mobile

Responsive typography may reduce size, but body copy still needs enough vertical space for comfortable reading.
